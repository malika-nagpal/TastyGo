TastyGo Requirements Document

This document defines the functional and non-functional requirements for the TastyGo food-ordering platform.

1. Introduction

1.1 Purpose

The purpose of this document is to outline the requirements for the TastyGo application. TastyGo is a web-based food delivery platform that connects customers, restaurant clients, and administrators to enable efficient ordering, menu management, and payment processing.

1.2 Scope

The system will allow:

  • Customers to register, browse menus, place orders, and make payments.
  • Restaurant clients to manage menus, receive orders, update order statuses, and view sales reports.
  • Administrators to monitor overall system activity, manage user accounts, and handle customer service tasks.

1.3 Definitions and Acronyms

  • Customer: End-user placing orders.
  • Restaurant Client: Business user managing menu and orders.
  • Administrator: User overseeing system operations and quality.
  • Menu: Digital listing of available food items.
  • Order: Request for food delivery or pickup.
  • SPMP: Software Project Management Plan.

1.4 References

  • CP317 Food Requirements (provided)
  • SPMP - Group 8 (provided)
  • IEEE Software Requirements Specifications Standard

1.5 Overview

This document is organized into sections describing the overall system, detailed functional requirements, logical database requirements, software system attributes, and version history.

2. Overall Description

2.1 Product Perspective

TastyGo is a standalone web application built using modern web technologies (HTML, CSS, JavaScript, and a backend language). The application will integrate with secure payment gateways and provide a responsive design for various devices.

2.2 Product Functions

  • User account registration and management.
  • Menu browsing, searching, and filtering.
  • Order placement, customization, and tracking.
  • Secure payment processing and receipt generation.
  • Restaurant menu management and order dispatching.
  • Administrative reporting and user management.

2.3 User Characteristics

The target users range from tech-savvy customers to restaurant managers and administrators. The system is designed with an intuitive UI to accommodate varying technical expertise.

2.4 Constraints

  • High concurrency during peak hours.
  • Compliance with payment security standards (e.g., PCI-DSS).
  • Browser compatibility with modern web standards.

2.5 Assumptions and Dependencies

  • Users have reliable internet access.
  • The application will interface with third-party payment and POS systems.
  • Development tools and frameworks remain current throughout the project lifecycle.

3. Specific Requirements

3.1 Functional Requirements

  • FR1: The system shall allow customers to create, update, and delete their accounts.
  • FR2: The system shall enable restaurant clients to add, edit, and remove menu items, including prices and images.
  • FR3: The system shall process orders in real time, including order tracking and status updates.
  • FR4: The system shall support multiple payment methods (credit card, wallet, etc.) and generate electronic receipts.
  • FR5: The system shall allow administrators to manage user accounts and review system analytics.

3.2 Logical Database Requirements

  • DB1: The database shall securely store user profiles with unique identifiers.
  • DB2: The database shall maintain detailed records of orders, transactions, and menu items.
  • DB3: The system shall support scalability and high availability through optimized database design.

3.3 Software System Attributes

3.3.1 Performance

  • The system shall support at least 1000 concurrent users with acceptable response times.

3.3.2 Security

  • All sensitive data must be encrypted both in transit and at rest.
  • The system shall adhere to industry-standard security protocols.

3.3.3 Portability

  • The application shall be accessible via all major web browsers and mobile devices.

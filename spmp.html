Software Project Management Plan (SPMP)

TastyGo Food Delivery Platform

Version 1.0 — 03/01/2025

1. Overview

1.1 Project Summary

1.1.1 Project Purpose, Goals, and Objectives

TastyGo is designed to provide a streamlined food delivery solution connecting customers, restaurant clients, and administrators. The platform aims to deliver an intuitive user experience, reliable order processing, and comprehensive management tools.

  • Goal 1: Develop a user-friendly interface for all actors.
  • Goal 2: Ensure reliable order and payment processing.
  • Goal 3: Provide robust reporting and analytics for administrators and restaurant clients.

1.1.2 Assumptions and Constraints

  • Team members will attend all scheduled meetings and adhere to deadlines.
  • The platform will run on all modern web browsers and mobile devices.
  • Integration with secure payment gateways and third-party systems is assumed.
  • Development tools and frameworks will remain current during the project lifecycle.

1.1.3 Project Deliverables

  • Fully functional TastyGo application
  • Requirements Document
  • Software Project Management Plan (SPMP)
  • Software Quality Assurance Plan (SQAP)
  • Object-Oriented Analysis and Design Documents
  • Test Plan and Documented Source Code
  • Maintenance Manual

1.1.4 Schedule and Budget Summaries

No monetary budget is allocated for this course project. The timeline is as follows:

  • Requirements: Due January 31, 2025
  • SPMP: Due February 7, 2025
  • Object-Oriented Analysis: Due March 7, 2025
  • Object-Oriented Design: Due March 21, 2025
  • Final Submission: Due April 4, 2025

1.1.5 Project Success Criteria

  • Scope: 100% coverage of required functionality.
  • Schedule: Milestone deadlines are met.
  • Quality: Defect density remains below 5% post-release.
  • Stakeholder Satisfaction: Positive feedback from the client and users.

1.2 Stakeholder Management & Governance

Stakeholders: Instructor (Client), Project Managers, Team Members.
Governance: Project Managers (e.g., Samir Bani and Rusanth Pirabakaran) oversee day-to-day operations, and the instructor approves scope changes.

1.3 Evolution of the Plan

The SPMP is a living document. It will be updated throughout the project based on client feedback, milestone reviews, and changes in scope or requirements.

5. Managerial Process Plans

5.1 Work Plan

The work plan is structured around major milestones including Requirements, SPMP, Object-Oriented Analysis, Object-Oriented Design, and Final Submission. Each team member is assigned tasks in accordance with their role.

5.2 Control Plan

  • Requirements Control: Regular meetings and documented code reviews.
  • Schedule Control: Milestone tracking with bi-weekly progress reviews.
  • Quality Control: Continuous integration, automated testing, and peer reviews.

5.3 Risk Management Plan

Risks include schedule delays, integration issues, and potential technical hurdles. Mitigation strategies involve frequent testing, continuous stakeholder communication, and contingency planning.

5.4 Close-out Plan

The project will be closed out upon successful integration, complete documentation, and final client sign-off.

6. Technical Process Plan

6.1 Process Model

The project will follow an iterative, Unified Process model with incremental deliverables.

6.2 Methods, Tools, and Techniques

  • Languages: HTML, CSS, JavaScript, and a server-side language
  • Tools: Visual Studio Code, GitHub, CI/CD pipelines
  • Techniques: Code reviews, unit testing, integration testing

6.3 Infrastructure Plan

Development will primarily be local with code maintained in a centralized GitHub repository.

6.4 Product Acceptance Plan

Final acceptance will be based on meeting all requirements, passing QA tests, and client approval.

7. Supporting Process Plans

7.1 Configuration Management

All artifacts will be managed using Git with regular backups and versioning.

7.2 Documentation Plan

Documentation will include design documents, test plans, user guides, and maintenance manuals.

7.3 Quality Assurance Plan

The QA plan includes unit tests, integration tests, and code reviews to ensure adherence to coding standards and requirements.

7.4 Problem Resolution Plan

Issues will be escalated to Project Managers, and if necessary, the instructor will be consulted for resolution.

8. Team Member Participation & Rating

Each team member will log their contributions. At project end, peer evaluations will be conducted and documented.

9. Software Quality Assurance (SQA) Plan

9.1 Quality Objectives

  • Maintain a defect density below 1 per 1000 lines of code.
  • Ensure 95% of test cases pass before final delivery.
  • Perform continuous integration and code reviews.

9.2 Roles and Responsibilities

The QA Tester leads testing; Project Managers oversee quality control; Developers ensure code standards; Documentation Specialists maintain updated reports.

9.3 Standards and Procedures

All processes will adhere to IEEE SPMP standards and internal guidelines.
